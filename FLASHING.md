# Flashing from Android — Phase 3

**Use `LUMINA_STUDIO.bin` at address `0x0`.** This is a full 4 MiB raw flash image, not an OTA/application image. Writing it overwrites existing firmware, settings and filesystem data in the first 4 MiB. Back up anything needed first. Use a normal development board without secure boot/flash encryption or restricted download mode.

1. Confirm the board has an **ESP32-C3 and 4 MiB flash**, using the board/module documentation or flash ID reported by the flasher. Identify whether the USB connector goes to native USB Serial/JTAG or a USB-UART bridge (e.g. CP210x or CH34x).
2. Install [ESPFlash for Android](https://play.google.com/store/apps/details?id=io.serialflow.espflash). Its [vendor documentation](https://serialflow.io/en/espflash/) lists ESP32-C3 native USB and USB-UART support; the [OTG guide](https://serialflow.io/en/blog/how-to-flash-esp32-from-android-otg/) describes flashing a factory image at `0x0`. Compatibility with your specific board and phone is not yet tested.
3. Use a data-capable cable and an OTG-capable phone/adapter. Enable OTG if the phone requires it. Grant the app USB permission, and close other apps using the USB device. If it cannot connect, hold **BOOT**, tap **RESET/EN**, then release **BOOT**. Follow the board's documentation if its buttons differ. Native USB may re-enumerate; select the new device if asked.
4. Select wired USB flashing, confirm the tool detects ESP32-C3, pick `LUMINA_STUDIO.bin` and set the offset to `0x0`. Keep the image's flash settings if asked. Start at 115200 baud if there are connection issues. Do not select OTA mode.
5. After writing, reset with BOOT released. If the tool does not reconnect, unplug/replug, regain USB permission, and open the USB serial monitor at **115200**. Send `?` in the serial terminal to print the per-device AP password and diagnostics. Join `LUMINA-STUDIO`, choose to stay connected if Android warns there is no internet, then open **http://192.168.4.1/** explicitly (not HTTPS). If the terminal has a line-ending setting, any option works; only `?` is acted on.

If the phone cannot power the board reliably, try a compatible powered OTG hub. If native USB is unsupported, try a board connector with a supported USB-UART bridge, or use the board manufacturer's documented UART connection with a compatible **3.3 V logic** adapter. [ESP32 Loader](https://play.google.com/store/apps/details?id=com.bluino.esp32loader) advertises OTG and several bridge drivers but does not clearly document C3 and raw `0x0` support; only use it if both can be confirmed. Do not assume Chrome on Android exposes desktop Web Serial or that a USB serial terminal can also flash firmware. An incompatible phone/board/app combination may require another Android device or a compatible board/adapter.

Espressif reference: [ESP32-C3 boot mode](https://docs.espressif.com/projects/esptool/en/latest/esp32c3/advanced-topics/boot-mode-selection.html).
